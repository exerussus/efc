# Changelog

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — [SemVer](https://semver.org/lang/ru/).

## [0.1.0] — не выпущено

### Добавлено
- Стандарт `efc/1` (черновик): раскладка канала, атомарная запись, вызов `requests → active → done`, пакеты,
  ожидание человека, сроки и отзыв без гонки, отмена, корзина вместо удаления у клиента и `trash.clean`
  (по запросу, клиентом при 50+ файлах и сервером раз в сутки), пульс и восстановление после перезапуска,
  `instance` против чужих и синхронизированных папок, `howToStart`, пути через корни, `inbox` и `state`,
  поиск каналов, коды выхода и стандартные `reason`.
- JSON Schema: `request`, `active`, `result`, `cancel`, `alive`, `channel`, `inbox`, `channels-index`;
  примеры файлов канала, проверенные схемами.
- `efc-core` (Rust): сервер (`Handler` + `Server::start`), клиент (`call`, `wait`, `withdraw`, `cancel`, `take`,
  поиск каналов), проверочный набор (13 проверок).
- `efc`: клиент (`list`, `help`, `call`, `batch`, `wait`, `result`, `cancel`, `diag`, `trash`), `init`, `check`,
  `serve` — белый список консольных программ, постоянные аргументы, пределы времени, подтверждение человека.
- Срок запроса ограничивает и выполнение: к сроку — просьба отмениться, через 30 с — итог с кодом 5.
- `serve`: программа в своей группе процессов — отмена и предел времени останавливают и её дочерние процессы;
  итог не ждёт оставшиеся фоновые процессы дольше 2 с; строка подтверждения экранируется; вопрос снимается при
  отмене или по сроку; Ctrl+C — штатная остановка.
- Сервер: повтор переименования и удаления при блокировках Windows (5/32/33), повтор id не выполняется и после
  перезапуска, паспорт проверяется на ходу, `trash.clean` проходит полную очередь, имя машины — из ОС.
- Клиент: живость только по смене `seq`; чужие запросы не отзываются; имена устройств Windows не годятся в id.
- Тесты без внешних утилит: команды сервера в сквозных тестах — сам `efc __helper …` (скрытая команда),
  поэтому `cargo test` целиком идёт и на Windows, включая остановку дочерних процессов.
- Проверено на связке Windows (сервер) ↔ ВМ (клиент): вызов 47 мс по медиане; на одной машине Windows — 21 мс.
- Вызов — около 20 мс (опрос раз в 20 мс у сервера и клиента в первые 2 с ожидания); через общую папку ВМ —
  125–210 мс.
- `build.cmd` (Windows) и `build.sh` (статический Linux-бинарник).
- Отладка: `--trace` / `EFC_TRACE` — журнал обеих сторон в `<канал>/trace/*.jsonl` (коды ошибок ОС и повторы
  rename, сколько запрос ждал сервер, опоздания пульса); `efc trace` — журнал по времени, по вызову; `efc selftest`
  — поведение файловой системы машины (блокировки Windows, длинные пути, кириллица, часы) и сервер с клиентом в
  одном процессе; `efc bench` — задержки вызова с разбивкой.
